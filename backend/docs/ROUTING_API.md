# API Маршрутизации с GNN

## Обзор

API маршрутизации использует графовую нейронную сеть (GNN) для оптимизации маршрутов посещения клиентов. Система учитывает временные окна, приоритеты клиентов, обеденные перерывы и другие факторы.

## Endpoints

### 1. Проверка статуса системы

**GET** `/api/jacobs/routing/status`

Проверяет доступность модели и статус системы.

**Ответ:**
```json
{
  "model_available": true,
  "model_path": "/path/to/model.pth",
  "device": "cuda" or "cpu",
  "status": "ready" or "model_not_found"
}
```

### 2. Оптимизация маршрута

**POST** `/api/jacobs/routing/optimize`

Оптимизирует маршрут для всех объектов пользователя.

**Заголовки:**
- `Authorization: Bearer <token>`

**Ответ:**
```json
{
  "tour": [0, 3, 1, 2, 4],
  "total_distance": 45.2,
  "total_time": 480.5,
  "total_time_hours": 8,
  "total_time_minutes": 0,
  "route_points": [
    {
      "object_number": 1,
      "address": "ул. Примерная, 1",
      "latitude": 47.1234,
      "longitude": 39.5678,
      "arrival_time": "09:00",
      "visit_duration": 30,
      "is_lunch_break": false,
      "client_rating": 75.0,
      "client_level": "VIP",
      "dynamic_criterion": 5
    }
  ],
  "lunch_breaks": [false, false, true, false, false],
  "success": true,
  "message": "Маршрут успешно оптимизирован. Посещено 5 точек из 5."
}
```

## Поля ответа

### RouteResponse
- `tour` - Порядок посещения точек (индексы)
- `total_distance` - Общая дистанция в км
- `total_time` - Общее время в минутах
- `total_time_hours` - Часы общего времени
- `total_time_minutes` - Минуты общего времени
- `route_points` - Детальная информация о каждой точке
- `lunch_breaks` - Информация об обедах
- `success` - Успешность операции
- `message` - Сообщение о результате

### RoutePoint
- `object_number` - Номер объекта
- `address` - Адрес объекта
- `latitude` - Широта
- `longitude` - Долгота
- `arrival_time` - Время прибытия (HH:MM)
- `visit_duration` - Длительность посещения в минутах
- `is_lunch_break` - Был ли обед перед этой точкой
- `client_rating` - Рейтинг клиента
- `client_level` - Уровень клиента (VIP/Standard)
- `dynamic_criterion` - Динамический критерий

## Логика работы

1. **Получение данных**: API извлекает все датасеты и клиентов пользователя из БД
2. **Подготовка данных**: Данные преобразуются в формат, понятный GNN модели
3. **Оптимизация**: GNN модель строит оптимальный маршрут
4. **Учет ограничений**:
   - Временные окна клиентов
   - Обеденные перерывы (13:00-14:00)
   - Приоритеты клиентов
   - VIP статус
5. **Формирование ответа**: Результат структурируется и возвращается клиенту

## Временные ограничения

- **Начало рабочего дня**: 09:00
- **Обеденный перерыв**: 13:00-14:00
- **Время на посещение**: 30 минут на точку
- **Базовые временные окна**: 09:00-18:00 (если не указаны в БД)

## Обработка ошибок

- `404` - Нет загруженных датасетов
- `500` - Ошибка загрузки модели или оптимизации
- `401` - Неавторизованный доступ

## Требования

- PyTorch >= 1.9.0
- NumPy >= 1.21.0
- Модель должна быть доступна по пути: `/backend/app/model/improved_gnn_dynamic.pth`
