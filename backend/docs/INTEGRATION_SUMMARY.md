# Интеграция GNN модели в FastAPI бекенд

## Обзор интеграции

Успешно интегрирована графовая нейронная сеть (GNN) в FastAPI бекенд для оптимизации маршрутов посещения клиентов. Система использует предобученную модель `improved_gnn_dynamic.pth` для построения оптимальных маршрутов.

## Что было реализовано

### 1. API Endpoints

#### `/api/jacobs/routing/status` (GET)
- Проверяет доступность модели
- Возвращает статус системы
- Не требует авторизации

#### `/api/jacobs/routing/optimize` (POST)
- Основной endpoint для оптимизации маршрута
- Требует авторизации
- Возвращает полную информацию о маршруте

#### `/api/jacobs/routing/stats` (GET)
- Получение статистики по данным пользователя
- Требует авторизации
- Возвращает аналитику без выполнения оптимизации

### 2. Схемы данных

#### RouteResponse
Полный ответ с информацией о маршруте:
- Порядок посещения точек
- Общая дистанция и время
- Детальная информация о каждой точке
- Информация об обедах

#### RoutePoint
Информация о конкретной точке маршрута:
- Координаты и адрес
- Время прибытия
- Рейтинг и уровень клиента
- Динамический критерий

#### RouteStats
Статистика по маршруту:
- Количество точек
- Распределение VIP/Standard клиентов
- Средний рейтинг
- Оценка эффективности

### 3. Интеграция с базой данных

Система автоматически:
- Извлекает все датасеты пользователя
- Получает связанных клиентов
- Учитывает временные окна клиентов
- Использует базовые значения (09:00-18:00) если данные отсутствуют

### 4. Логика оптимизации

#### Входные данные:
- Координаты объектов из таблицы `datasets`
- Временные окна из `clients` (start/end) или `datasets` (work_start_time/work_end_time)
- Рейтинги клиентов из `clients`
- Приоритеты из `datasets.dynamic_criterion`
- Уровни клиентов из `datasets.client_level`

#### Обработка:
1. Подготовка данных в формате для GNN
2. Вычисление матриц расстояний и времени
3. Запуск оптимизации через GNN модель
4. Учет временных ограничений и обедов
5. Формирование итогового маршрута

#### Ограничения:
- Время начала: 09:00
- Обеденный перерыв: 13:00-14:00
- Время на посещение: 30 минут
- Учет временных окон клиентов

### 2. Запуск сервера
```bash
python main.py
```

### 3. Тестирование
```bash
python test_routing.py
```

### 4. API документация

## Примеры запросов

### Проверка статуса
```bash
curl http://localhost:8000/api/jacobs/routing/status
```

### Оптимизация маршрута
```bash
curl -X POST http://localhost:8000/api/jacobs/routing/optimize \
  -H "Authorization: Bearer <token>"
```

### Получение статистики
```bash
curl http://localhost:8000/api/jacobs/routing/stats \
  -H "Authorization: Bearer <token>"
```

## Требования к модели

- Модель должна находиться по пути: `/backend/app/model/improved_gnn_dynamic.pth`
- Формат: PyTorch state_dict
- Архитектура: ImprovedGNNQNetwork

## Обработка ошибок

- `404` - Нет данных пользователя
- `500` - Ошибки модели или оптимизации
- `401` - Неавторизованный доступ

## Производительность

- Модель загружается один раз при первом запросе
- Оптимизация выполняется на GPU (если доступно) или CPU
- Время выполнения зависит от количества точек (обычно < 1 секунды)

## Безопасность

- Все endpoints требуют авторизации (кроме status)
- Данные пользователей изолированы
- Валидация входных данных
